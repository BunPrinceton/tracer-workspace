FlyWire Link Troubleshooting

Why old FlyWire / Neuroglancer share links sometimes fail to load the segmentation — and how to fix them. Short version: it's almost always your browser session's auth token, not the link.

What “HTTP error 0” actually means

Error retrieving metadata for volume graphene://…/fly_v31: Fetching "" resulted in HTTP error 0 does not mean the data is gone. The fly_v31 production segmentation is still live. HTTP error 0 means the browser's fetch never completed — the auth handshake was blocked before a real request was even formed (note the empty "" URL).

In a scene, the EM image and brain mesh are public sources, so they load regardless. Only the segmentation (graphene://…prodv1.flywire-daf.com/…) needs authentication — which is why “EM loads, segmentation doesn't” is the classic signature.

The thing the segmentation needs is a live, per-session middleauth token for the prodv1 data server. That token is not stored in the link — it lives in your browser session (cookies on the flywire-daf.com / daf-apis.com domains) and is attached when the fetch happens. So an old link isn't carrying a “stale token”; your session just doesn't have a live one yet.

The one-step fix that covers almost every case

Open any FlyWire scene first and let it finish authenticating (complete any Google login popup). That establishes the prodv1 token for your whole session — then every old link you open afterward loads immediately. The usual failure is opening a specific old link as the very first thing, before your session has a token.

If a link still won't load

Work down this list — they're all about getting a valid prodv1 token to the viewer. You do not need to edit the link or its source; the native ngl.flywire.ai viewer authenticates the source for you once your session is good.

  1. Confirm you're logged in. Account icon (top-right) should show your name. Note: being “logged in” (your Google identity) is not the same as holding a live prodv1 token — see below.
  2. Allow popups for ngl.flywire.ai, then reload. A blocked Google-login popup is the #1 cause of “I refreshed and nothing happened.”
  3. Allow cross-site cookies for [*.]flywire-daf.com and [*.]daf-apis.com. The token rides on cross-site cookies between these domains; if they're blocked, the handshake dies and you get HTTP error 0.
  4. On Brave: drop Shields (the lion icon) for ngl.flywire.ai. Brave blocks third-party cookies / cross-site requests by default, which severs the handshake. Note: Shields-down is separate from the third-party-cookie setting — check both.
  5. Refresh a stale token. If error 0 returns mid-session, the token expired: account menu → Log Out → Log back in (mints a fresh token). Or clear site data for flywire-daf.com + daf-apis.com and reload.
  6. Use the real viewer. Open links in FlyWire's own ngl.flywire.ai, not a generic neuroglancer.org / Spelunker tab — a generic viewer doesn't do the middleauth handshake at all.
“But I am logged in and it still says HTTP error 0”

Login and token are two different things:

  • Login = your Google identity. One session, shown in the account menu. Shared across every link.
  • Token = a per-data-server middleauth credential (here, for prodv1.flywire-daf.com). It's what the segmentation fetch actually uses, it's obtained per session, and it expires on its own — independent of whether the account menu shows you as logged in.

So “logged in but error 0” = your identity is fine but the prodv1 token wasn't established or has gone stale. The levers are steps 3–5 above (cookies / Brave / log out–in). All your scenes point at the same prodv1 server, so one good token fixes them all at once.

What's actually inside these links (and why none of it is “broken”)
  • ?json_url=…/nglstate/… — a portable state stored on FlyWire's server. Works anywhere you're authenticated.
  • ?local_id=… — a scene saved in only the one browser profile that created it. Not portable: it won't load on another machine/profile (there's no server copy). If it loads for you but the segmentation errors, that's the token issue above — not the link.
  • A bare graphene://https://prodv1… source is fine — the native viewer authenticates it for you. You do not need to add any prefix or edit the source.

Make a local_id scene durable: once it loads, hit Share to mint a json_url link — that one survives browser/profile changes.

Outdated (red) segment IDs after it loads

Separate issue. Once the segmentation loads and you can select/deselect again, the red “outdated” root IDs can be refreshed — FlyWire root IDs change when neurons are merged/split. For bulk updates, fafbseg can map old IDs to their latest roots (R: fafbseg::flywire_latestid() and friends; Python: the fafbseg.flywire helpers). Get the volume loading first.

History

This page used to host a “link restorer” that rewrote sources to add a middleauth+ prefix (plus a bookmarklet and a userscript). We removed all of that after discovering the prefix was never the real fix: the native viewer authenticates bare sources itself, and the rewriting/auto-reloading actually interfered with the viewer's own auth. The real cause — and the real fix — is the session token, as above. The old tooling lives in git history if ever needed.
